# Окно меню эксперимента и журнал полёта

```
python -m multiuav menu
```

Окно собирает параметры попытки, показывает значок «пульт подключён», кнопки «Старт» и «Стоп».
После конца попытки остаётся открытым: можно менять параметры и запускать следующую.

На Ubuntu для окна нужен tkinter: `sudo apt install python3-tk`. Значок пульта работает при
установленном pygame: `pip install -e .[gamepad]`.

## Что делает «Старт»

1. Проверяет параметры (понятное сообщение, если что-то не так).
2. Создаёт папку попытки `<папка журнала>/<код участника>/<дата_время>/`.
3. Запускает отдельный процесс `python -m multiuav run ...` — так же, как из терминала. Окно с
   полётом не делит процесс и не мешает ему. Пульт во время попытки читает только процесс
   полёта; окно в это время пульт не опрашивает.

«Стоп» посылает процессу Ctrl+C: менеджер штатно заканчивает полёт и сохраняет всё (на Windows
процесс просто завершается, журнал по дронам к этому моменту уже на диске).

## Папка попытки

```
runs/<код участника>/2026-10-30_14-05-33/
  drone0.csv        ведущий
  drone1.csv ...    ведомые
  experiment.json   параметры попытки из меню
  scenario.yaml     сценарий, как он был запущен (с поправками из меню)
  track.csv         общий журнал `run --out` (все дроны в одном файле)
  summary.json      итог: сколько финишировало и разбилось
  run.log           вывод процесса: по нему разбирают ошибки
```

## Журнал по дронам (`drone<N>.csv`)

Одна строка — один шаг управления (20 раз в секунду). Стандартный CSV: разделитель «,», дробная
часть через «.».

| Столбец | Что это |
|---|---|
| `pc_time_ms` | время компьютера, мс от 1970 года (`time.time_ns() // 1_000_000`, те же системные часы, что у записи стиков `sticks log` и у айтрекера); берётся сразу после опроса симулятора, а не после отправки команд, поэтому не отстаёт ни при тормозах симулятора, ни при медленной отправке; по нему журналы склеиваются |
| `t` | время симуляции, с (как в `track.csv`) |
| `north`, `east`, `altitude` | положение, м; высота вверх |
| `yaw_deg` | курс, градусы (0 — север, по часовой стрелке положительный) |
| `collided` | 1, если дрон столкнулся |
| `rc_roll`, `rc_pitch`, `rc_throttle`, `rc_yaw`, `rc_mode` | каналы пульта 1000..2000 и режим; пусто, если на этом шаге дрону команда не отправлялась |
| `blackout` | 1, если экран оператора чёрный |

Стики после столкновения пишутся настоящие, если сценарий не останавливает дрон при столкновении
(`stop_on_collision: false`, как в `rc_group.yaml`).

`blackout` берётся из метода `SimBackend.blackout()`. Сейчас он всегда возвращает `False`: тот,
кто делает затемнение, переопределяет его в нужном бэкенде.

Журнал по дронам можно включить и без меню: `python -m multiuav run <сценарий> --flight-log <папка>`.

## Какие параметры что делают

| Поле | Действие |
|---|---|
| Код участника | имя папки `runs/<код>/...`: буквы, цифры, `_`, `-`, `.` |
| Дронов (с ведущим) | ведущий + ведомые (то же, что `--followers N` = N+1) |
| Когда конец | «по времени» — ровно столько секунд, финиш сценария отключён; «на финише» — до финишной зоны сценария, длительность служит пределом |
| Режим полёта | AltHold или Acro для ведущего с пульта (как `--mode`); если в сценарии есть `mode_switch`, решает тумблер на пульте |
| Сценарий, симулятор, адрес | для отладки; пульт работает только в Cosys-AirSim, Unreal нужно запустить заранее |

Пока **только записываются** в `experiment.json` (поле `not_applied_yet`) и не влияют на полёт:
длительность затемнения, ветер, камеры ведомых, алгоритмы помощи.

## Когда появится автозапуск Unreal

Команда в `start_attempt` (`multiuav/experiment.py`) заменяется вызовом
`python -m multiuav launch <папка попытки>/experiment.json`; `experiment.json` уже лежит в папке.
